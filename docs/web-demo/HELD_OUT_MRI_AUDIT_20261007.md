# Published-MRI PDF extraction audit (2026-10-07)

## Decision

This is a **bounded document-extraction audit**, not evidence of medical translation quality, page reconstruction, or clinical safety. Three final published articles and six physical pages were attempted; none was excluded. The originally frozen MTQC build had a reproducible P1 long-table row/value split on Bhalerao page 4. A local, unpublished correction and three red/green regressions restore readable rows on that page without reproducing a new two-column failure on Rankin page 3. **The Kalluvila one-row Table 1 still loses a reliable five-header/five-value association in automatic mode. This P1 remains open; do not describe this local build as fully table-faithful or public-release-ready.**

The original build was frozen in [the prespecified protocol](HELD_OUT_MRI_PROTOCOL_20261007.md) before any page/output inspection. [The visual truth checklist](HELD_OUT_MRI_VISUAL_TRUTH_20261007.md) was written from original renders before opening either extraction arm. It names every selected page's headings, major reading transitions, figures/captions, equations/units, and every table data-row identity. All locally rendered page PNGs, source PDFs, exact excerpts, raw text outputs, and geometry JSON remain under ignored `output/research/held-out-20261007/`; they are not redistributed in Git. The subsequent fix was developed against this audit, so the post-fix column is a **development retest**, not a new independent held-out benchmark.

## Method and denominators

The simple arm joined the **same PDF.js `getTextContent()` `str` items** in native array order with spaces. The frozen MTQC arm used the same items, the browser's 1.25-scale geometry transform, and `recoverReadingOrder(..., 'auto')`. The local correction used the same input, with only the full-width numeric-table heuristic changed. We compared all three against the previously fixed visual checklist, not against each other. `P/F/–` below means pass/fail/not-present, in the order **simple baseline / frozen MTQC / local corrected MTQC**. A `pass` is a bounded, visually checked extraction relation, not medical correctness. `Omission` covers selectable text/fragment retention; image-internal text is scored separately. A figure-caption pass means the caption remains next to its visual figure and is identifiable, even if `Fig. n` prints on the second line; the reversed label placement is still noted as a formatting defect.

Attempted **3/3 candidates, 6/6 selected pages**; excluded **0**. The six page checklists yield **30 scorable page-category items**, **0 unscorable**, and **6 not-present** categories per arm. Checklist passes were **19/30** baseline, **18/30** frozen MTQC, and **21/30** local correction; these are raw engineering checks on six selected pages, **not** an accuracy estimate, medical benchmark, or an independent post-fix test set. All 866 selectable PDF.js fragments across the six pages were retained exactly once in both MTQC runs (104+59+301+73+215+114), which says nothing about their correct order. Visually present text outside a selected physical page, e.g. paragraph continuations, was never counted.

For tables specifically, the visual checklist contains one 5-column/one-row Kalluvila table, 12 patient-characteristic rows and 4 segmentation rows on Rankin page 3, and 39 scanner/model rows on Bhalerao page 4: **56 visible data-row identities**. The simple stream keeps the row-associated tokens in order on all 56. The frozen MTQC stream visibly keeps only the first five complete Bhalerao row associations plus the 16 Rankin rows (**21/56**); after the first Bhalerao block it lists model/counts first and slice/voxel data far later. The local correction restores those 39 row sequences, yielding **55/56** readable rows, but the five Kalluvila rating headers/values remain split in automatic mode. These row counts are manual structural checks, not validation that every voxel value has been semantically parsed into a cell; inherited blank cells and wrapped voxel strings remain review-dependent.

## Reproduced failures, causes, and safeguards

1. **P1 fixed locally — Bhalerao page 4:** frozen output ran `Prisma 27`, `Prisma_fit 82`, ... through `Intera 49`, then emitted the corresponding `208`, `175, 176, ...`, `150, 170, 184` slice/voxel strings much later. The simple PDF.js stream had these adjacent in source order. Root cause: `numericTableBands` established a full-width table using two strong early rows but allowed only rows with multiple *pure* numeric fragments and a short page-width distance; inherited blank cells and comma-separated slice lists ended the band. The correction retains contiguous aligned rows after strong table establishment, tests long/sparse rows, and checks that `Table n` is a genuine left-edge marker with a compact multi-cell header. An intermediate correction wrongly grouped Rankin's right-column Table 2 plus left prose; an explicit half-column/inline-marker regression and real-page retest removed that regression. Final Rankin page 3 matches its original two-column ordering; the source remains local only.
2. **P1 open — Kalluvila page 8:** the five headers and single Likert row are correctly sequential in native PDF.js, but MTQC auto mode reports two columns and splits the first two header/value cells from the last three; a `†` footnote fragment arrives between them. The numeric-table detector intentionally requires at least two data rows, so it does not protect this one-row table. Review mode `single` can be selected manually; default automatic output remains unsafe to claim as faithful table extraction. This exact table stays in the failure denominator and needs a new, independent regression/fix before release.
3. **Known math fidelity failure — Kalluvila page 4 and Bhalerao page 9:** the visual equations have numbered parentheses, superscripts and grouping. Both raw and enhanced text streams reorder some glyph fragments or parentheses (`TP/ TP( + FN)` instead of the visually grouped `TP/(TP+FN)`; fragmented `G`, `f_dec`, and `ψ` around Kalluvila equation 1). The source image must be checked, and extracted math must not be treated as verified. This is not repaired by the table fix.
4. **Figure-internal labels not recovered:** Kalluvila MRI/architecture panels, Rankin's `S1`, plot labels and rotated side labels, and Bhalerao's CV workflow boxes include text visible in source images but absent from the searchable PDF layer. The live UI checks image operations and warns that image labels are absent; browser regression confirms the warning, and submit remains disabled until the reviewer checks approval. This is a **generic page-level warning**, not per-figure missing-label detection, so expert comparison and manual transcription remain required. No OCR of embedded images was silently inferred.
5. **Caption typography defect:** geometric grouping often emits the first words of `Fig. n` captions before the `Fig. n` token. The caption/figure stays adjacent in the rendered workbench, so the bounded link check above passes, but plain-text export is not citation-quality.

No privacy/review-gate violation (P0) was reproduced in this sample. The workbench displays the source page and editable text, warns that table row alignment is unverified when a table region is detected, warns about image-internal labels on searchable pages, and requires explicit review before live translation. These safeguards reduce silent misuse but **do not** turn structurally wrong extraction into a passing result. We made **zero paid Nebius calls** and performed no translation-quality/clinical adjudication.
